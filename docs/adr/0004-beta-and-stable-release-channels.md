# Beta and Stable release channels

Releases follow two Channels. All work lands on the long-lived `develop` branch through pull requests and ships as GitHub pre-releases: `v0.x.y` before 1.0.0, `v1.x.y-beta.N` after it. `main` stays unreleased until the `develop` → `main` promotion PR sets the version to `1.0.0`, after which `main` carries the stable `v1.x.y` releases. Both branches are protected: changes arrive only through pull requests, and merging one that raises the workspace version past the latest `v*` tag makes the release workflow tag the commit, build Windows and Linux installers and publish the GitHub Release. We chose this over a trunk on `main` with beta tags so that every commit on `main` is a stable release, over a manual tag-and-draft flow so that the reviewed release PR is the only approval a release needs, and over a `beta` branch so that the integration branch keeps its name, its default-branch setting and its rulesets across the 1.0.0 boundary.

## Consequences

`main` is not the branch contributors work on until 1.0.0, so `develop` is the repository's default branch. Feature PRs squash-merge; the promotion PR uses a merge commit, because a squash would leave the two branches permanently diverged. After 1.0.0 a hotfix goes through a PR on `main` and is merged back into `develop`. The workspace `Cargo.toml` version is the single source of truth and the app, the CLI and the installers share it.

The repository is public with an Apache-2.0 licence, so GitHub Releases is both the developer record and the download host; the marketing site only renders what the Releases API lists. Pre-releases are invisible to `releases/latest`, so consumers must list releases instead. Winget manifests point at the same asset URLs but are submitted only for `0.x.y` and stable versions, because winget orders versions with a pre-release suffix poorly. Windows installers are unsigned during the beta; signing is required before `v1.0.0`. Branch protection needs a public repository on the organisation's current GitHub plan, so the repository goes public before the rules are enabled.
